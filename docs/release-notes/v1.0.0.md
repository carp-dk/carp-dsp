# CARP-DSP v1.0.0

The first major release of CARP-DSP (CARP Data Science Pipeline): a workflow
framework for mobile and wearable sensing analytics, built on CARP Core. An
analysis is a graph of versioned steps with typed ports; the planner checks a
workflow before it runs, and every run leaves a bundle that records what produced
each output and can be run again.

## What is in this release

**Authoring**
- Workflows in a YAML DSL: environments declared once, steps with typed input and
  output ports, explicit port-to-port connections.
- A certified step library (`carp.dsp.steps`): fifteen steps in three tiers,
  referenced with `uses:` and pinned by content hash in `steps.lock`.
- Steps written as commands, Python, R, or Kotlin (run as a command on the shared
  task runtime).

**Planning**
- Plan-time checks of formats, CARP data types, missing producers, undeclared
  outputs, cycles and environments, each error placed at its step.
- Protocol-linked inputs, checked against the study protocol that collects them.
- Deterministic plans: the same workflow version gives the same plan on every
  machine.

**Execution**
- Pixi, Conda, R and system environments, each recorded with what it contained;
  Pixi lock files installed exactly.
- Each step runs in its own process with its own input, output and log folders;
  writes outside them are reported.
- Step caching: a step whose command, environment and inputs are unchanged reuses
  its earlier outputs.

**Sharing**
- Run bundles with the plan, the report, environment records and an RO-Crate
  (Workflow Run Crate) file listing every file with its SHA-256.
- Export to a CWL v1.2 Workflow and to Snakemake.
- Workflow packages with metadata, protocol references and a content hash,
  published through a registry interface.

**Evaluation**
- The harness behind the paper's evaluation (`carp.dsp.demo`), with the recorded
  results in `carp.dsp.demo/eval_results/`. See [REPRODUCING.md](../../REPRODUCING.md).

## Requirements

- JDK 17, Pixi, and Docker for the Linux runs of the evaluation.
- Built from source with CARP Core (`278d2a57`, `feature/core-analytics`) and
  health-workflow-interfaces (`c332d00a`) as sibling checkouts; see the README.
- Kotlin 2.4.0, Gradle 8.14.4 (wrapper).

## Known limitations

- Docker environments can be declared and exported, but are not run.
- Isolation is by process and folder within a declared environment, not by
  container.
- Kotlin steps must be vendored in this repository; steps for others to retrieve
  are scripts.
- Outputs agree across processors up to floating-point rounding.
- The `in-process` task type in the YAML schema is not supported by the runner
  and will be removed.
